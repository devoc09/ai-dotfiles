# Language

- 返答は必ず日本語で書くこと。英語の skill・ドキュメント・コードを読んだ場合も、説明・報告・質問はすべて日本語で行う。
- コード、識別子、エラーメッセージの引用、コミットメッセージは英語のままが自然な場合はそのままでよい。

# コード・テスト・コミット・コメントの原則

t_wada の次の原則に従って開発する。

- **コードには How**：処理をどのように実現するかを、実装・命名・構造で表現する。
- **テストコードには What**：何が満たされるべきかを、テスト名と検証内容で表現する。実装手順をなぞるのではなく、期待する振る舞い・仕様を検証する。
- **コミットログには Why**：なぜ変更が必要だったのかを記録する。背景・問題・判断理由を伝え、差分を読めば分かる変更内容の列挙だけで終わらせない。
- **コードコメントには Why not**：なぜ別の実装や一見自然な選択肢を採用しなかったのかを記録する。制約・落とし穴・トレードオフを説明し、コードから明らかな処理の逐語的な説明は避ける。

これらを実装、テスト作成、コミット作成、レビューの際に適用する。説明が不要な箇所に形式的なコメントや文章を増やさず、後から読む人に必要な意図を適切な場所へ残す。
